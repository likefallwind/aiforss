# 8.1 偏见来源与测量：从数据到模型的链路

算法偏见并非凭空产生，它贯穿于机器学习系统的每一个环节。要系统性地理解偏见，必须从"数据—模型—目标"三条链路逐一分析。<!-- SLIDE_BREAK -->

## 训练数据偏见

训练数据往往是社会现实的映射，而社会现实本身存在系统性歧视。例如，若用历史招聘数据训练简历筛选模型，过去的录用决定中隐含的性别歧视会被模型学习，导致模型倾向于排斥女性候选人。再比如，若一个文本语料库大量来源于新闻报道，其中对某些群体的描述往往与负面事件相关联，语言模型就会学到这些关联。数据偏见的本质是：**样本不具代表性或标签本身带有偏见**。<!-- SLIDE_BREAK -->

## 模型架构偏见

模型架构偏见体现在模型的学习机制会放大或固化某些模式。线性模型倾向于学习简单的线性关联，但如果特征与敏感属性（如性别、地域）存在伪相关，模型会将这种关联编码进去。深度神经网络由于其高表达能力，尤其容易捕捉训练数据中的细微统计规律——这些规律中可能包含社会偏见的痕迹。举例来说，图像生成模型在训练集中不同肤色的样本数量差距显著时，生成的图像就会出现系统性的人口比例失衡。<!-- SLIDE_BREAK -->

## 目标函数偏见

目标函数偏见是更隐蔽的源头。模型在优化"预测准确率"或"点击率"等指标时，若这些指标在子群体上分布不均，模型会天然地倾向于优化多数群体的表现。例如，一个信用评分模型如果整体准确率为85%，但在低收入群体上准确率只有60%，模型仍然可以通过忽视少数群体来维持高整体准确率。这里的关键是：**默认的优化目标没有考虑公平性约束**。<!-- SLIDE_BREAK -->

## 核心概念一：算法偏见的全链路来源

算法偏见贯穿于机器学习系统的每一个环节。要系统性地理解偏见，必须从"数据—模型—目标"三条链路逐一分析：

- **训练数据偏见**：样本不具代表性或标签本身带有偏见
- **模型架构偏见**：模型的学习机制会放大或固化某些模式
- **目标函数偏见**：默认的优化目标没有考虑公平性约束

理解这三条链路是后续测量和消解偏见的基础。<!-- SLIDE_BREAK -->

## 偏见的测量框架：敏感属性与受保护群体

测量偏见需要先明确"敏感属性"和"受保护群体"。

**敏感属性**指与歧视相关的属性，如性别、种族、年龄、宗教等。

**受保护群体**指在这些属性下处于不利地位的子群体。

明确了这两个概念后，才能使用相应的公平性指标进行测量。<!-- SLIDE_BREAK -->

## 统计均等性（Statistical Parity）

衡量不同群体在正类预测中的比例是否接近。公式上，要求 $P(\hat{Y}=1|A=0) \approx P(\hat{Y}=1|A=1)$，即无论属于哪个受保护群体，获得正预测的概率大致相同。例如，在贷款审批中，女性获批比例应与男性接近。

**但这一指标有一个前提**：正类预测在两个群体中的基础比率应该本就接近，否则可能掩盖真实的群体差异。<!-- SLIDE_BREAK -->

## 均等机会（Equalized Odds）

在统计学上要求 $P(\hat{Y}=1|Y=y, A=0) = P(\hat{Y}=1|Y=y, A=1)$，对每个真实标签 $y$，两个群体的预测阳性率相同。

这意味着模型不仅要对不同群体公平，还要在"把好人误判为坏人和把坏人误判为好人"两种错误上保持一致。相比统计均等性，均等机会更精细，因为它区分了不同的预测结果。<!-- SLIDE_BREAK -->

## 校准性（Calibration）

要求模型对不同群体输出相同的置信度时，实际正类率应相同。例如，若模型预测某申请人的违约概率为30%，无论该申请人是男是女，其真实违约概率都应接近30%。

校准性是衡量模型公平性最严格也是最直观的指标之一。<!-- SLIDE_BREAK -->

> **概念**：三类指标分别对应不同的公平性定义，不存在一个"最好"的指标。选择哪一个取决于具体场景的伦理要求——有时追求统计均等性，有时追求均等机会，有时追求校准性。
>
> **示例**：在犯罪风险评估（COMPAS）案例中，研究者发现黑人被告被错误标记为高风险的比率几乎是白人被告的两倍。这说明模型在校准性上可能存在问题——对不同种族群体，相同的风险分数背后对应的真实风险并不相同。
>
> **易错点**：三大指标之间存在数学上的不可同时满足（Impossibility Theorem），即在患病率不同的群体上，不可能同时满足统计均等性和均等机会。初学者容易陷入"追求一个指标完美"而忽视其他指标的做法，应该理解这是一种权衡而非最优解。<!-- SLIDE_BREAK -->

```python
# 偏见测量示例：计算统计均等性差异
import numpy as np

def statistical_parity_difference(y_pred, sensitive_attr):
    """
    计算统计均等性差异：P(Ŷ=1|A=1) - P(Ŷ=1|A=0)
    接近 0 表示公平，偏离 0 表示存在偏见
    """
    group_0 = sensitive_attr == 0
    group_1 = sensitive_attr == 1
    
    # 计算各组正预测率
    pos_rate_group0 = np.mean(y_pred[group_0])
    pos_rate_group1 = np.mean(y_pred[group_1])
    
    return pos_rate_group1 - pos_rate_group0

# 示例数据
y_pred = np.array([1, 0, 1, 0, 1, 0, 1, 0])      # 模型预测
sensitive_attr = np.array([0, 0, 0, 0, 1, 1, 1, 1])  # 敏感属性（受保护 vs. 非受保护）

spd = statistical_parity_difference(y_pred, sensitive_attr)
print(f"统计均等性差异: {spd:.3f}")
# 解读：差异为正表示模型对受保护群体更倾向于给正预测
```<!-- SLIDE_BREAK -->

# 8.2 社会刻板印象检测：性别、种族、地域偏见识别

## 核心概念三：刻板印象的嵌入机制与检测方法

社会刻板印象通过语言、图像和结构化数据三条路径嵌入 AI 系统。理解嵌入机制是检测的前提。<!-- SLIDE_BREAK -->

## 词嵌入中的偏见

词嵌入（如 Word2Vec、GloVe）通过大量文本学习词语的向量表示，而文本中的社会偏见会被编码在词语的代数关系中。经典案例是：输入"man is to computer programmer as woman is to ?"后，词嵌入倾向于输出"homemaker"（家庭主妇），这直接反映了职业性别刻板印象。类似地，种族偏见也体现在人名与职业词汇的关联上——某些族裔的名字与负面词汇的距离更近。<!-- SLIDE_BREAK -->

## 词嵌入直接偏见测量的核心技术：WEAT

**词嵌入直接偏见测量的核心技术是 WEAT（Word Embedding Association Test）**，它借鉴了心理学中的内隐关联测验（IAT）。WEAT 通过计算两组目标词（如"男性名字"与"女性名字"）与两组属性词（如"职业词汇"与"家庭词汇"）之间的余弦相似度差异，来量化词嵌入中隐含的性别或种族偏见程度。若男性名字与职业词汇的关联显著强于女性名字，则说明词嵌入中存在职业性别偏见。<!-- SLIDE_BREAK -->

## 语境嵌入中的偏见

语境嵌入中的偏见比词嵌入更隐蔽。BERT 等基于 Transformer 的语境模型会根据上下文动态调整词向量，此时偏见的检测需要考虑词语在不同语境下的表现。例如，"doctor"一词在男性语境的句子中可能携带不同的语义信息，在女性语境的句子中又是另一种含义。检测语境偏见的方法通常是对比模型在不同语境下对同一核心词的编码，以及模型对含敏感属性的句子的情感分析结果。<!-- SLIDE_BREAK -->

## 图像与多模态偏见

图像与多模态偏见体现在视觉模型中。面部识别系统对深肤色人群的识别准确率普遍低于浅肤色人群，这不是模型架构的缺陷，而是训练数据的不均衡——多数公开的人脸数据集以浅肤色样本为主。更隐蔽的是生成模型中的偏见：文本到图像生成模型在接收到"a professional"时倾向于生成以白人男性为主的图像，反映了训练数据中职业形象的统计偏差。<!-- SLIDE_BREAK -->

## 核心概念四：偏见消解的层次与策略

偏见消解可以在三个阶段进行：**数据层面**、**模型训练层面**和**输出层面**。

三个层次各有侧重，互为补充。<!-- SLIDE_BREAK -->

## 数据层面消解

**数据层面**的核心策略是重采样与数据增强。重采样的目标是通过过采样少数群体样本或欠采样多数群体样本来平衡训练数据。但要注意，简单的随机重采样可能引入过拟合——尤其在少数群体样本稀缺的情况下。更精细的方法是 SMOTE（合成少数类过采样技术），它通过在少数群体样本之间插值来生成合成样本。数据增强则通过替换敏感属性的表达方式（如将"he"替换为"she"并保持语义不变）来扩充平衡语料。<!-- SLIDE_BREAK -->

## 模型训练层面消解：对抗训练

**模型训练层面**的主流方法是**对抗训练**。对抗训练的核心思想是引入一个对抗判别器（adversarial discriminator），它试图从模型的中间表示中预测敏感属性，而主模型的目标是同时优化主任务性能和"欺骗"对抗判别器。通过这种零和博弈，模型被迫学习不包含敏感信息的表示，从而在预测时不会依赖这些属性。对抗训练的数学表达可以理解为一个多目标优化问题：主任务损失 $\mathcal{L}_{main}$ 与对抗损失 $\mathcal{L}_{adv}$ 之间的权衡。<!-- SLIDE_BREAK -->

## 输出层面消解：阈值调整

**输出层面**的方法是在模型预测后追加一步后处理。最经典的是**阈值调整**：对不同群体使用不同的决策阈值。例如，若模型对男性群体的预测校准良好，但对女性群体整体偏低，则可以为女性群体设置更低的阈值，使得两个群体的真阳性率趋于一致。后处理的优点是无需重新训练模型，适合在部署阶段快速修复偏见问题；缺点是可能牺牲部分整体准确率。<!-- SLIDE_BREAK -->

> **概念**：数据层面消解关注"输入数据的质量"，训练层面消解关注"模型学习的过程"，输出层面消解关注"最终决策的公平性"。三者互补，没有银弹。
>
> **示例**：一个情感分析模型在评价"亚洲留学生"和"本地学生"的作文时，给前者打出了平均低15分的成绩。这可能是训练数据中"亚洲面孔+低分作文"的高频共现造成的。解决思路包括：在数据层面补充更多亚洲学生的优秀作文样本；在训练层面引入对抗机制使模型忽略学生族裔信息；在输出层面检查不同族裔群体的评分分布并进行阈值校准。
>
> **易错点**：对抗训练并非万能。对抗判别器的能力是瓶颈——如果对抗判别器太弱，它无法捕捉到敏感信息，模型就不被充分约束；如果太强，模型可能矫枉过正，连合法的、与敏感属性相关的信号也被过滤掉（比如在医学诊断中，性别本身就是重要的诊断依据，此时不应该消除性别信息）。<!-- SLIDE_BREAK -->

# 简化的对抗训练框架示意
import torch
import torch.nn as nn

class FairClassifier(nn.Module):
    def __init__(self, input_dim, hidden_dim):
        super().__init__()
        # 主特征提取器
        self.feature_extractor = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim)
        )
        # 主任务分类器
        self.task_classifier = nn.Linear(hidden_dim, 1)
        # 对抗判别器（试图从特征中预测敏感属性）
        self.adversary = nn.Linear(hidden_dim, 1)

    def forward(self, x):
        features = self.feature_extractor(x)
        task_pred = self.task_classifier(features)
        adversary_pred = self.adversary(features)
        return task_pred, adversary_pred, features

# 8.4 数据治理框架与合规性监管要求

## 核心概念五：数据治理的基本框架与公平性实践

数据治理（Data Governance）是一套管理数据资产的政策、流程和技术的系统性框架，在 AI 公平性语境下，其核心目标是**确保数据从采集到使用的全生命周期中，偏见被识别、监控和控制**。<!-- SLIDE_BREAK -->

## 数据治理框架的核心环节

一个完整的数据治理框架通常包含以下环节：

- **数据来源审计**——追踪训练数据的采集渠道，评估数据提供者的选择是否存在系统性偏差
- **数据质量评估**——检查不同群体的样本量是否均衡、特征分布是否存在显著差异
- **模型审计**——在部署前和部署后定期使用公平性指标对模型进行评估
- **投诉与纠偏机制**——为受到不公平对待的用户提供申诉通道<!-- SLIDE_BREAK -->

## 国际监管框架：EU AI Act 与美国

在国际层面，**欧盟《人工智能法案》（AI Act）**将AI系统按风险等级分类，高风险 AI 系统（如用于招聘、教育评估、信贷评分的系统）须满足严格的合规要求，包括进行偏见测试、提供透明的使用说明、以及接受第三方审计。

美国则更多依赖行业自律和部门性法规（如 Equal Credit Opportunity Act 适用于金融领域），但缺乏统一的 AI 公平性立法。<!-- SLIDE_BREAK -->

## 中国法规要求

在中国，《互联网信息服务算法推荐管理规定》和《生成式人工智能服务管理暂行办法》均明确要求算法不得"对公民在交易价格等交易条件上实行不合理的差别待遇"，实质上是对算法歧视的规制。这些规定要求平台记录训练数据的来源，定期开展算法伦理评估，并对用户投诉进行响应。<!-- SLIDE_BREAK -->

> **概念**：合规不等于公平——满足法规的最低要求不一定能保证模型在道德上无偏见。企业应该将治理框架从"被动合规"转向"主动公平设计"。
>
> **示例**：某银行引入自动信贷系统后，监管机构要求其提供不同 ZIP code 地区的批准率报告。如果发现某个低收入社区的批准率显著低于其他地区，即便没有明确使用种族信息，银行也需要证明这一差异是由合法的信用因素（而非历史歧视的代理变量）导致的。
>
> **易错点**：仅删除敏感属性列（"color-blind"方法）不足以消除偏见。敏感属性往往与其他特征存在相关性（如邮编与种族、姓名与性别），模型可以通过代理变量间接学习到被删除的属性信息。这在技术上被称为**代理歧视（proxy discrimination）**，是数据治理中需要特别审计的场景。<!-- SLIDE_BREAK -->

## 学习要点总结

本课围绕"偏见从哪来、如何测、怎样消、如何管"四个问题展开。核心在于理解偏见不是单一环节的问题，而是数据、模型、目标和部署环境共同作用的结果。测量偏见需要选择与业务场景匹配的公平性指标，没有万能的最优解，只有基于伦理判断的权衡。偏见消解的三条路径——数据重采样、对抗训练、阈值后处理——各有适用场景和局限性，实践中通常需要组合使用。数据治理则是将公平性从技术问题上升为制度问题，是 AI 系统长期可信运营的保障。<!-- SLIDE_BREAK -->

**进阶方向提示**：对抗训练的具体实现细节与梯度反转层的数值稳定性优化，可参考 Goodfellow《Deep Learning》公平性章节；差分隐私与公平性之间的张力是当前活跃的研究方向，建议阅读 Abbe 等人的综述；各国 AI 监管框架的动态演进可关注欧盟 AI Office 和中国信通院的政策跟踪报告。
